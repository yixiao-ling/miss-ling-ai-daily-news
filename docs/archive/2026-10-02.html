这是对主流"切块+embedding+向量召回"范式的直接挑战。向量 RAG 的痛点在于：切块破坏语义结构、相似度不等于相关性、多跳与全局性问题上召不准。PageIndex 的思路是把文档组织成层级化索引结构（标题/章节/摘要），让 LLM 像人翻目录一样"按索引推理定位"再取原文，可显著提升长文档、结构化文档的准确率与可解释性。代价是每次检索需多次 LLM 调用，延迟与成本高于 ANN 召回。工程上可行的折中是：向量做粗排，推理做精排与多跳定位。对做知识库、法律/财报问答的产品，值得评估作为增量检索层。
This directly challenges the mainstream "chunk + embedding + vector recall" paradigm. Vector RAG suffers from chunking that breaks semantic structure, similarity that isn't relevance, and poor recall on multi-hop or global questions. PageIndex organizes documents into a hierarchical index (headings, sections, summaries) so the LLM navigates like a human reading a table of contents, then fetches raw text—improving accuracy and interpretability on long, structured documents. The trade-off is extra LLM calls per query, raising latency and cost above ANN recall. A practical hybrid: vectors for coarse retrieval, reasoning for fine ranking and multi-hop grounding.
