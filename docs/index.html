这是对产品差异化的一次警告：如果所有人都用同一个底座模型做建议类产品，输出必然趋同，护城河就只剩上下文与数据。技术上，SFT/RLHF 的"众数化"效应、候选生成单一化（temperature、多样性衰减）是根因，可行路径是引入用户长期记忆、个人画像 RAG、多候选重排与显式个性化约束。产品层意味着"通用问答"价值递减，垂直场景+私有上下文+可解释推理链才是差异化，也提示评测体系要加入多样性/个性化指标而非只看有用性。
A warning about product differentiation: if everyone builds advice products on the same base model, outputs converge and the only moat left is context and proprietary data. Technically, SFT/RLHF mode-seeking effects and collapsed candidate diversity (low temperature, decaying entropy) are the root cause. Practical paths include long-term user memory, personal-profile RAG, multi-candidate reranking, and explicit personalization constraints. For products, generic Q&A loses value while vertical scenarios plus private context and explainable reasoning chains win — and evals should add diversity/personalization metrics, not just helpfulness.

A pragmatic template for "rules engine + LLM" layering: deterministic checks (pattern matching, dataflow, taint analysis) guarantee low hallucination, low cost and reproducibility, while the LLM only handles reasoning that needs context — keeping token spend and false positives manageable on huge codebases. The lesson for builders is task decomposition and routing rather than dumping everything on a model. Competitively it targets CodeRabbit, Qodo and GitHub Copilot Code Review; its OpenAI/Anthropic compatibility layer enables model swapping, private deployment and cost tuning, making it a good fit for an enterprise code-quality platform.
